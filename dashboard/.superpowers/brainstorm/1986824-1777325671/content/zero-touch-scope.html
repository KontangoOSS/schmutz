Zero-touch provisioning — full scope

Three sub-projects in dependency order. Each needs the one above it to exist first.

1

Identity & naming standard

Foundation

The taxonomy everything else depends on. Without this, SCIM pushes land in the wrong places and Ziti attributes don't map to anything.

Ziti
Attribute taxonomy
#role-dev, #app-ticketarr
Zitadel
Group → role mapping
group:developers → #role-dev
Bao
Policy path convention
kontango/apps/{name}/
Forgejo
Org/team structure matches Zitadel groups
Proxmox
Realm + role mapping from Zitadel groups
Deliverable: a spec document + seed data in Bao catalog that all systems reference
2

Approval workflow engine

Orchestration

What fires when someone is approved. A sequential pipeline — each step confirms success before the next runs.

Decision engine
flip approved=true
→
Zitadel
create user, assign groups
→
SCIM push
Forgejo + Proxmox
→
Ziti attrs
update identity
→
Tinkerbell
machine provisioning
→
Email
notify user
Lives in decision-engine or a new workflow service. Needs rollback/retry per step. NATS events at each stage.
3

Browzer dashboard

End-user surface

Post-approval view. The user sees only what they're assigned to — services and machines, nothing else.

Services panel
Ziti services bound to this user's groups — links, status, access method
Machines panel
Enrolled devices assigned to this human — status, last seen, platform
ziti-dash browzer plugin. Reads from Ziti + Bao catalog using the identity from phase 1.
