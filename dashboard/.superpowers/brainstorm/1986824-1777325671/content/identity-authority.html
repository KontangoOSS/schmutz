Where does identity live?

You have four systems that can own an identity record. Before we design naming standards and tagging, we need to agree on which one is authoritative for each identity type.

Current systems

Ziti
Network identity + access policy. Every enrolled machine/service gets a cert. Controls who can reach what.
Bao
Secrets + service catalog. AppRole per service, entity aliases, policy enforcement. Knows what each service is allowed to read.
Zitadel
Human SSO + OIDC. Manages human users, OIDC clients per app, SCIM-capable. Proxmox + Forgejo already federate to it.
Proxmox / Forgejo
Platform identity. VMs/LXCs have IDs, Forgejo has users + org memberships. Both can consume SCIM from Zitadel.

Which model fits how you think about this?

A

Zitadel is the authority — everything federates to it

Humans, services, and machines all have a Zitadel identity. Ziti gets OIDC tokens from Zitadel. Bao trusts Zitadel via JWT auth. Proxmox/Forgejo get SCIM-synced users. One login, one place to revoke.

Pros

  • Single source of truth
  • Revocation is immediate everywhere
  • SCIM already supported

Cons

  • Zitadel becomes a critical dependency
  • Machine identities feel awkward in an SSO system
B

Split authority — Ziti owns machines, Zitadel owns humans

Machines enroll via Ziti OTT (cert-based, no password). Humans authenticate via Zitadel OIDC. Bao trusts both. Services register in Bao catalog with a Ziti identity. Proxmox/Forgejo federate to Zitadel for humans only.

Pros

  • Right tool for each identity type
  • Machine enrollment doesn't depend on SSO being up
  • Clean separation of concerns

Cons

  • Two systems to maintain
  • Need a mapping layer (Bao entity aliases) to link them
C

Bao is the registry — others are consumers

Bao entity catalog is the master record for all identities (humans, machines, services). Ziti identities, Zitadel users, and Proxmox VMs all get an entity alias in Bao. The catalog is the join table.

Pros

  • Bao already has the service catalog
  • Policy is colocated with identity
  • One audit log

Cons

  • Bao is a secrets store, not an IdP
  • Human lifecycle management is awkward
