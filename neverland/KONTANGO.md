## Hey there 👋

Thanks for checking out this project. It's built by the team at **Kontango** — a small group of engineers who believe that great infrastructure shouldn't cost a fortune.

Every tool we build is **open source**, **self-hostable**, and designed to help teams and small businesses run their own software affordably and confidently. No vendor lock-in. No surprise bills. Just tools that work.

The **Kontango Open Source Project (KONOSS)** is where it all comes together — production-ready infrastructure, real alternatives to expensive SaaS, and a community that believes you should always own your stack.

---

## 🚀 What We're Building

We organize our work into focused groups, each tackling a different layer of the stack:

| Group | Focus | Key Projects |
| :--- | :--- | :--- |
| **kustodian** | Infrastructure & platform tools | Templatarr, Deploy, TangoKore |
| **kore** | Core applications | Ticketarr |
| **kreate** | Provisioning & orchestration | Kreator, Omni-Kluster |

### Ecosystem Highlights

🎫 **Ticketarr** — Project management and issue tracking, built for teams that want to own their workflow. Self-hosted, Docker-native, and packed with features you'd expect from tools 10x the price.

🧱 **Templatarr** — The scaffold generator that created this project. Every Kontango repo starts here — consistent structure, best practices baked in, ready to build.

⚙️ **TangoKore** — Infrastructure-as-code library for Kontango deployments. Scripts, configs, and automation for standing up your stack.

🖥️ **Kreator** — End-to-end Proxmox provisioning for LXC, LXD, and VM nodes. PXE boot, external secrets, automated infrastructure configs.

🌐 **Omni-Kluster** — Multi-node cluster orchestration built on Kreator. Define your cluster, define your network, and let it build.

> You might notice the `-arr` naming convention. It's our thing.

## 🔧 How We Work

A few principles that run through everything we build:

| | Principle | What It Means |
| :---: | :--- | :--- |
| 🏠 | **Self-hosted first** | If it can run on your hardware, it should |
| 🐳 | **Docker-native** | Every service ships as a container |
| 🔐 | **Secrets done right** | Phase in production, `.env` for local dev |
| 📜 | **MIT licensed** | Use it, fork it, ship it |
| 📝 | **Conventional commits** | `feat:` `fix:` `docs:` `refactor:` `test:` `chore:` |

**Our stack:** Forgejo for git · Caddy for reverse proxy · OpenZiti for zero-trust networking · Cloudflare for DNS · Phase for secrets management

It's the same infrastructure we run in production — and it's all open source.
